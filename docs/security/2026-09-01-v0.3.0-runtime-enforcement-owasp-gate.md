## Security scope

- Data classification: public operator-controlled status templates; opaque run, Session, account, channel target, and timer metadata held in memory only.
- Trust boundaries: untrusted user/model content, typed hook events, plugin config, OpenClaw route context, outbound channel adapter, and the external messaging platform.
- Write capability: at most one automatic start-card attempt and one automatic long-tool waiting-card attempt per eligible run under default settings.
- Forbidden data: prompt, session messages, system prompt, tool parameters/results, raw errors, secrets, customer content, and sensitive paths are not read into automatic messages or retained in enforcement state.
- Eligibility: exact `trigger=user`, `runId`, account id, provider, and current target are required. Missing or conflicting route metadata skips automatic delivery.
- Authentication and channel credentials remain OpenClaw-owned. The plugin neither authenticates users nor stores credentials.
- ASVS v5.0.0: `NOT_APPLICABLE_WITH_EVIDENCE`; this plugin exposes no Web/API endpoint or authentication surface. Equivalent controls are typed-hook, route-isolation, delivery-failure, package, and runtime-load tests.

## Threat model and abuse cases

- Cross-channel/account/thread delivery: controlled by exact route reconstruction, account requirement, Session-route consistency checks, per-run route ownership, and negative tests.
- Prompt injection selecting destination or automatic content: controlled by static configured templates, metadata-only route fields, and no reads of prompt/messages/systemPrompt. Throwing-proxy tests fail if those fields are accessed.
- Duplicate storm: controlled by run-first delivery identity, concurrent start claims, the existing unknown-outcome guard, one waiting card per run, and bounded state.
- Gateway degradation: controlled by run capacity, per-run timer capacity, TTL limits, one-shot timers, timer cancellation, and a bounded four-second wait for the start attempt.
- Status failure blocking user output: controlled by internal error containment and an explicit `{ outcome: "pass" }` from the fail-closed `before_agent_run` hook.
- Background leakage: cron, heartbeat, non-user triggers, missing run id, missing account, route-less, and conflicting-route contexts skip automatic delivery.
- Unknown platform outcome: no retry or alternate-recipient fallback is attempted.

## Findings, residual risk, and rollback

- Independent re-review of exact commit `83d46336fbe138b581a43469b06e87cac24e0e3f`: PASS; P0/P1/P2/P3 `0/0/0/0`.
- Residual operational limit: OpenClaw's outbound adapter call does not expose a plugin-level cancellation signal. The hook waits at most four seconds, never retries unknown delivery, and the enforcement state remains bounded; the underlying adapter owns its network timeout.
- Live acceptance is intentionally not executed in this implementation scope. Short-turn, long-tool, error, restart, and two-route Discord smokes remain deployment Human Gates.
- Immediate behavior rollback: set `enforcementMode` to `prompt` or `off` and restart Gateway.
- Full package rollback: reinstall pinned `v0.2.2` and restore its matching config; do not delete Sessions or messages.
