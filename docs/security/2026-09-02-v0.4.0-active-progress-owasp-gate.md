## Business-logic and attacker review

- A runtime start card cannot satisfy live acceptance by itself.
- A high card count cannot satisfy semantic acceptance.
- `PARTIAL` or `UNVERIFIED` typed-tool visibility cannot become `SUPPORTED`; it yields `LIMITED` wait coverage and requires model-authored fallback evidence.
- An observable long-tool test must show exactly one wait fallback, preventing both silent omission and duplicate wait spam.
- A marker upgrade replaces only the managed block and preserves unrelated instructions.
- Tool comparison permits newly added UI Lab tools but rejects removal or ownership changes of existing tools.
- Evidence containing raw operational details is rejected even if every behavioral category is present.
- No queue acknowledgment, queue reordering, indefinite timer, customer-config mutation, Gateway restart, channel send, publish, or deployment is part of repository implementation.
